# 成品分集（每集约一小时）设计

日期：2026-10-20
状态：已实现并测试通过；**服务重启后对新任务生效**

## 1. 需求

用户原话（m02609）：

> 文章太大的时候做出来的MP3也过大，请按一小时左右切割，分成若干个文件，前面做过的山音和正在做的弑君者传奇都分，以后也按照整个标准，更新到CosyVoice的设定中

三个已确认的决策（AskUserQuestion）：

1. **只留分集，删掉整本大文件**；
2. 正在跑的《弑君者传奇》**等它跑完再切**，不动正在跑的任务；
3. 切点**尽量落在句子之间的停顿**，允许每集 55–72 分钟浮动（不切在半个词上）。

## 2. 实测依据

改之前《山音》的成品：**6.80 小时 / 467 MB 一个文件**。这种文件播放器拖着卡、
发不出去、也没法单独听某一段。切完是 7 集、每集 66.7 MB。

切点质量实测（`ffmpeg silencedetect -35dB / ≥0.4 秒`）：6 个切点全部命中真静音，
静音长度 1.25 / 0.94 / 0.58 / 0.41 / 0.40 / 0.69 秒——不是整点硬切。

## 3. 设计

- **集数**：`ceil(total/max)` 到 `floor(total/min)` 之间取最接近 60 分钟的那个；
  区间为空时（例如 2.5 小时：2 集=75 分钟超上限、3 集=50 分钟低于下限）
  **以上限为准**，宁可短一点也不留超长文件。
- **切点**：在理想切点前后各 5 分钟里跑 `silencedetect`，取**离理想位置最近、
  且不短于 0.4 秒**的静音中点；一个都没有才硬切（并允许它硬切）。
- **安全**：切完把每集时长加起来和源文件比，差超过 2 秒就**保留源文件并报错**，
  绝不"切坏了还删原件"。
- **命名**：`<篇名> 第NN集.mp3`，落在同一目录。
- **不分集**：`episode_seconds = 0` 时完全不切，行为和以前一样。

## 4. 挂在哪儿

- `episode.py`（新）：`probe_duration / plan_count / find_silences / plan_cuts /
  split_file / fmt`，是唯一实现。
- `app.py` `_run_doc()`：一篇文档**合成完成且没被中断**之后，立刻调用
  `episode.split_file(..., delete_source=True)`；失败只记 `episode_error`，
  成品 MP3 原样保留（分集是锦上添花，不能因为它把成品弄丢）。
- `scripts/split_mp3_episodes.py`：同一个函数的手工命令行入口，补切历史成品用。
- 设置：`config.py` `EPISODE_SECONDS=3600`、`EPISODE_MIN_SECONDS=55*60`、
  `EPISODE_MAX_SECONDS=72*60`、`EPISODE_CHOICES=(0,30,60,90 分钟)`；
  界面「成品分集」下拉框，随 `/api/settings` 持久化到 `settings.json`。

## 5. 验证

`scripts/test_episode_split.py` → **28 项全过 / EPISODE_SPLIT_OK**：

- 集数：30 分钟→1、70 分钟→1、130 分钟→2、6.8 小时→7、24 小时→24、
  2.5/3.2/9/15.5 小时都在合理档位；
- 用 ffmpeg 造「9 秒音 + 1 秒静音」的音频，两个切点分别落在 199.5s / 409.5s，
  都在周期静音段内（`% 10 = 9.50s`）；
- 真切：3 个文件、名字 `第01/02/03集`、总时长 609.8s ≈ 源 610.0s、源文件已删；
- 时长不够时返回原文件且不删；
- `target=300s / min=240 / max=360`（界面的 30 分钟档）→ 2 集；
  `delete_source=False` 时源文件保留。

回归：`UNIT_PARALLEL_OK`、`RESUMETEST_OK`、`EBOOK_IMPORT_OK`、
`FRONTEND_GUARD_OK` 全部通过。
